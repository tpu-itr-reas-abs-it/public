# Abstract IT

Веб-приложение для управления проектами с диаграммой Ганта. Отвечает на пять
вопросов: какие есть задачи, кто за них отвечает, каковы сроки, как задачи
связаны между собой и **как сдвиг одной задачи влияет на весь проект**.

## Основной сценарий

1. Вход под тестовым аккаунтом.
2. Открыть проект «Запуск мобильного приложения».
3. На диаграмме Ганта видны сроки, статусы, связи и подсвеченный критический путь.
4. **Потянуть полосу задачи вправо** — сервер каскадно двигает зависимые задачи
   и сообщает, сколько задач затронуто и не срывается ли дедлайн.
5. Блок риска и счётчики состояний обновляются сразу; изменение прилетает
   другим участникам проекта по WebSocket без перезагрузки страницы.

## Что реализовано

### Бэкенд — [`backend/`](backend)

- **Проекты и команда.** CRUD проектов, участники с ролями `owner` /
  `responsible` / `viewer`, поиск пользователей по email и имени.
- **Задачи.** CRUD, фильтры по статусу, состоянию, ответственному и датам,
  поиск по названию и описанию, сортировка, пагинация.
- **Связи.** Тип `finish_to_start` с поддержкой лага. Граф зависимостей —
  строго ациклический: перед каждой вставкой ребра прогоняется топологическая
  сортировка, цикл отклоняется с кодом `409 task_cycle`.
- **Критический путь.** Полноценный CPM в два прохода: ранние и поздние сроки,
  резервы, сам путь восстанавливается как связная цепочка.
- **Анализ влияния.** `GET /tasks/{id}/impact` — сухой прогон сдвига без записи
  в базу, `POST /tasks/{id}/shift` — применение с каскадным пересчётом
  последователей. Оба возвращают список затронутых задач и прогноз окончания.
- **Контроль состояния.** Процент выполнения, взвешенный по длительности задач,
  счётчики по статусам и состояниям, оценка риска срыва с готовыми
  формулировками причин.
- **Реальное время.** WebSocket-канал проекта; события рассылаются через Redis
  pub/sub, поэтому работают при нескольких репликах приложения.
- **Дополнительно.** Комментарии к задачам, уведомления о просрочке из фонового
  воркера, экспорт проекта в JSON и CSV, представления «доска», «календарь» и
  «загрузка команды», кеш тяжёлых агрегатов в Redis.

Подробности: [схемы архитектуры](ARCHITECTURE.md)

### Фронтенд — [`frontend/`](frontend)

- **Вход и регистрация** с хранением пары токенов и автоматическим обновлением
  access-токена.
- **Список проектов** с прогрессом, счётчиками просрочек и ролью пользователя;
  создание проекта отдельным экраном.
- **Рабочая область проекта**: диаграмма Ганта, список задач, панель проекта,
  блок риска.
- **Интерактивная диаграмма Ганта** — собственная реализация, без сторонних
  библиотек: перетаскивание полосы меняет сроки, правый край тянется для
  изменения длительности, связи рисуются мышью между задачами. Три масштаба
  времени, линия «сегодня», подсветка критического пути и нарушенных связей.
- **Задачи**: создание и редактирование в диалоге, смена статуса, удаление,
  фильтр по состоянию и поиск по названию.
- **Команда и обсуждение**: диалог участников со сменой ролей, комментарии к задаче.
- **Экспорт** проекта в JSON и CSV прямо из интерфейса.
- **Реальное время**: подписка на WebSocket проекта с автоматическим
  переподключением; изменения других участников подтягиваются без перезагрузки.

## Запуск

Нужен только Docker.

```bash
cd backend
cp .env.example .env          # заменить JWT_SECRET и пароль БД
docker compose up -d --build
make seed                     # демо-данные и тестовые аккаунты
```

```bash
cd frontend
cp .env.example .env          # указать адрес API
docker compose up -d --build
```

Бэкенд поднимется на `:80`, фронтенд — на порту из `FRONTEND_PORT`.
Локальная разработка фронтенда — `npm install && npm run dev`, запросы к `/api`
проксируются на адрес из `VITE_DEV_API_TARGET`.

## Ограничения MVP

- Один тип связи между задачами — `finish_to_start` (с поддержкой лага).
- Календарь сплошной: выходные и праздники не исключаются из длительности.
- Нет иерархии задач, вех и трудозатрат в часах.
- Refresh-токены не отзываются на сервере — выход из системы удаляет их на клиенте.
- Уведомления только внутренние, без email и мессенджеров.
- Представления «доска», «календарь» и «загрузка команды» реализованы на бэкенде,
  но в интерфейс пока не выведены — основной сценарий строится вокруг Ганта.
- Предпросмотр последствий сдвига есть в API, но интерфейс применяет сдвиг сразу
  и показывает результат уведомлением.
- Автотесты покрывают доменное ядро; интеграционных тестов API нет.
